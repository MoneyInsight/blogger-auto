# 구글 블로거 애드센스용 글 — 모든 블로그 공통 지침 (예약 작업이 매번 읽음)

블로그별 값(블로그 키·라벨·정체성·주제·출처·문체·foot 등)은 예약 작업 지시문에 있다. 이 파일은 모든 블로그에 똑같이 적용한다.
★최우선 목표는 구글 애드센스 승인이다. 애드센스가 떨어뜨리는 가장 흔한 이유는 "가치가 낮은 콘텐츠"와 "같은 틀로 찍어낸 글"이다. 아래 규칙은 그 신호를 없애기 위한 것이다.

## 1. 주제
- 사람들이 실제로 검색하는 고민 1개 = 글 1편. 지금 시기(계절·월)에 검색이 몰리는 것을 우선한다.
- 같은 블로그에 이미 있는 글과 메인 키워드가 겹치면 쓰지 않는다(제목 목록을 먼저 본다).
- 사실(숫자·금액·날짜·기준·제도)은 WebSearch로 공식 출처에서 확인한 것만 쓴다. 확인 못 한 것은 쓰지 않는다.

## 2. 제목 — 매번 형태를 바꾼다
- 30~50자. 앞 15자 안에 메인 키워드(검색창에 치는 2~4단어). 숫자는 본문에 근거가 있을 때만.
- ★제목에 화자를 넣지 않는다: "셀러·사장·아빠·가장·두 아이·내가·제가" 금지. "~하던 내가 바꾼 N가지/순서/이유" 같은 틀 금지.
- 아래 6가지 형태 중 하나를 고르고, 같은 블로그 최근 4편과 끝맺음 단어가 2편 이상 겹치지 않게 한다.
  1) 질문형: "겨울철 실내 적정 습도는 몇 %일까? 가습기 없이 맞추는 방법"
  2) 방법·단계형: "패딩 세탁 방법 5단계, 집에서 물세탁할 때 주의점"
  3) 기준·조건형: "청년월세 지원 대상 조건, 월 최대 20만 원 받으려면 확인할 요건"
  4) 비교형: "파킹통장 CMA 차이는? 세금 낼 돈을 맡길 때 비교할 3가지"
  5) 원인·해결형: "아이폰 배터리 빨리 닳는 이유와 확인할 설정 4가지"
  6) 체크리스트형: "자동차보험 갱신 전 확인할 것 5가지"
- 과장·자극어 금지(충격·긴급·폭탄·털린다·무조건·100%·완치·특효). 본문이 실제로 답하는 내용만.

## 3. 본문 — 같은 틀 반복 금지
- ★첫 문장 = 메인 키워드 + 이 글의 핵심 답(검색 미리보기에 그대로 뜬다). "이 글은 ○○를 위해 쓴 글이다" 같은 정해진 도입 문장은 쓰지 않는다.
- ★자기소개 문장("나는 온라인 쇼핑몰을 운영하는 1인 사업자이자 두 아이 아빠다" 등)은 쓰지 않는다. 블로그 소개 페이지에 이미 있다. 경험은 글 내용에 필요할 때 한두 문장으로만, 구체 금액·날짜·사건을 지어내지 않고 쓴다.
- "~에 대해 바로 따라 할 수 있도록 핵심부터 정리한다", "헷갈리기 쉬운 부분을 먼저 짚고 순서대로 정리한다" 같은 상투 문장 금지.
- 구성은 아래 4가지 중 같은 블로그 직전 글과 다른 것을 고른다. 소제목 문구도 매번 새로 쓴다("마무리" 하나만 허용).
  A) 문제 → 원인 → 기준(표) → 해결 순서(ol) → 마무리
  B) 핵심 답 → 대상·조건(표) → 단계별 방법(ol) → 자주 하는 실수 → 마무리
  C) 상황별 비교(표) → 상황마다 할 일(h3) → 체크리스트(ol) → 마무리
  D) 오해 3가지 바로잡기(h3) → 올바른 기준(표) → 실천 순서(ol) → 마무리
- <h2> 4~5개, 각 <h2> 아래 <h3> 0~3개(소제목마다 다르게). 표 1개, 번호 목록 1개(3~7개 항목). 문장은 한 줄에 하나.
- 분량 공백 제외 1,500~1,900자. 일반론·같은 말 반복으로 채우지 않는다. 그 주제에만 해당하는 구체적인 기준·순서·주의점으로 채운다.
- 링크(<a>)·<h1>·FAQ·광고 문구·쿠팡·특정 제품/업체 추천 금지. 강조는 <b>만.
- ★참고 자료: spec의 "refs"에 실제로 확인한 공식 출처를 1~3개 "기관명 「자료·안내 이름」(2026년 ○월 확인)" 형식으로 넣는다(링크 없이 글자로만). 확인한 것이 없으면 넣지 않는다.

## 3-1. AI가 쓴 글처럼 보이지 않게 (애드센스 '가치 낮은 콘텐츠' 방지 — 가장 중요)
구글은 AI 사용 자체가 아니라 '누가 써도 똑같은 글'을 걸러낸다. 사람이 쓴 글의 신호를 넣는다.
- ★구체성: 일반론 대신 그 주제에서만 나오는 디테일을 쓴다 — 실제 메뉴 이름·설정 경로(예: 설정 > 배터리 > 충전 보호), 공식 기준의 정확한 숫자와 기준 시점, 신청 화면에서 헷갈리는 칸 이름, 계절·지역·상황별 차이.
- ★판단과 한계: "이 방법이 안 맞는 경우", "해 보니 굳이 안 해도 되는 것", "공식 안내와 실제 체감이 다른 점"처럼 의견과 단서를 1~2곳에 넣는다. 모든 걸 다 좋다고 하지 않는다.
- ★리듬: 문장 길이를 섞는다(아주 짧은 문장과 긴 문장). 문단마다 같은 3문장 구조로 쓰지 않는다. 소제목마다 <h3> 개수와 분량을 다르게 한다.
- ★숫자 틀 깨기: 모든 글을 "5가지/5단계"로 맞추지 않는다. 번호 목록은 내용에 맞게 3~7개, 숫자가 어색하면 제목에 숫자를 빼도 된다.
- ★AI 말투 금지(글 전체에서 합쳐 3번 넘게 나오면 발행 보류): "~하는 것이 좋다", "중요하다", "핵심은", "정리하면", "무엇보다", "이처럼", "결론적으로", "다양한", "효과적", "꼼꼼히", "첫째·둘째·셋째", "마무리하며", "알아보자/살펴보자", "도움이 될 것이다", "꼭 기억". 대신 "~하면 된다", "~부터 본다", "나는 ~했다"처럼 행동·사실로 말한다.
- ★예시 1개: 독자가 실제로 겪는 장면을 하나 구체적으로 보여 준다(예: "고지서에 적힌 납부기한이 지나면…"). 단 금액·날짜·사건을 지어내지 않는다.
- 마무리는 요약 반복 대신 "다음에 확인할 것 한 가지" 또는 "이럴 땐 전문가·기관에 묻는 게 빠르다" 같은 실제 다음 행동으로 끝낸다.

## 4. SEO (색인·노출 90점 이상)
- 첫 2문장 안에 메인 키워드. <h2> 1~2개와 <h3> 1개에 메인 키워드를 자연스럽게(마무리 소제목에는 넣지 않는다). 키워드 들어간 문단 3~12개. 제목의 핵심 단어가 본문에도 나온다. 이미지 alt에 메인 키워드.
- seo_gate.py는 위 2·3·3-1의 틀(AI 말투 3회 초과 포함)(제목 화자·'바꾼' 틀, 도입·자기소개 상투 문장, 최근 글과 같은 제목 끝맺음·첫 문장)을 어기면 항목당 -20점으로 보류한다. 지적된 문장은 기계적으로 고치지 말고 그 글 내용에 맞게 새로 쓴다.

## 5. 이미지
- images.json: thumb={"top": 블로그별 값, "main1": 독자·고민(최대 10자), "main2": 핵심 답(최대 10자), "badge": 글 성격에 맞게 매번 다르게("2026년 기준", "순서대로 정리", "체크리스트", "기준 한눈에", "직접 확인한 방법" 등 — 직전 글과 다르게), "bottom": 메인 키워드(12자 이내), "theme": blue/dark/light 중 직전 글과 다르게}, cards 2장(1장=핵심 기준 3가지, 2장=순서 요약; title 14자 이내, items 3개 각 18자 이내 "핵심|설명", theme은 thumb와 같게).
- img1.jpg는 표가 있는 섹션, img2.jpg는 번호 목록 섹션에 둔다.

## 6. 만들기·검사·발행 (Bash 1번, set -e)
- 글마다 /tmp/specN.json(tools/spec_example.json 형식: kw, meta, intro, sections, refs, foot, images) → D=posts/queue/<한국시간 YYYY-MM-DD-HHMM>-<접두어>-<영문슬러그>
- python tools/build_post.py /tmp/specN.json "$D" (분량·'다.' 종결·금지어·링크 검사, 실패 시 spec 고쳐 다시, 최대 2번) → python tools/make_images.py "$D" → python tools/seo_gate.py "$D" --fix (90점 미만이면 지적 항목을 직접 고쳐 다시, 최대 2번. 끝내 미달이면 그 글은 push하지 않는다).
- post.json의 meta = {"title", "labels", "blog", "series", "publish_at"} (블로그별 값). publish_at = 오늘 한국시간 랜덤(1편 08:00~14:59, 2편 15:00~21:59, 간격 3시간 이상, 지금보다 60분 이상 뒤, ISO +09:00).
- 통과한 글만: rm -rf tools/__pycache__; git add -A && git commit -qm "<블로그> 예약 발행: 제목" && git fetch -q origin main && git rebase -q origin/main && git push origin HEAD:main. push는 허락 묻지 말고 한다. 실패하면 fetch·rebase 후 재푸시 최대 5번(사이 5~10초).
- 확인: sleep 80; git fetch -q origin main && git checkout -q -B main origin/main; posts/published/<폴더>/post.json "status"가 SCHEDULED/LIVE인지, posts/failed·posts/last_error.txt 확인. 실패는 고칠 수 있으면 1번 재시도, 그래도 실패면 PushNotification 1번(<routine_summary> 안) "⚠️ <블로그> 예약 실패 — 이유 한 줄".
